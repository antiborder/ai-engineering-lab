
# AI Engineering Lab — Complete Implementation Specification

## 1. Product Vision

Build **one integrated AI Engineering Lab** containing five learning modules:

1. **LLM & AI Fundamentals**
2. **GenAI Systems Lab**
3. **AI Evaluation Lab**
4. **AI Inference Lab**
5. **AI Production / LLMOps Lab**

These are **not five independent applications**.

They are five modules of one application, connected through a shared AI artifact lifecycle:

```text
Understand
    ↓
Build
    ↓
Evaluate
    ↓
Optimize
    ↓
Deploy
    ↓
Monitor
    ↓
Improve
    ↺
```

The five modules correspond to:

```text
1. Fundamentals  → Understand
2. GenAI Systems → Build
3. Evaluation    → Measure
4. Inference     → Optimize
5. LLMOps        → Operate
```

The application should demonstrate that modern AI engineering is not simply "calling an LLM API", but a lifecycle of **building → evaluating → optimizing → deploying → monitoring → improving**.

---

# 2. Most Important Architectural Principle: Shared AI Artifacts

The central object connecting the five modules is an **AI Artifact**.

For example, the user creates a RAG application:

```text
GenAI Systems
      ↓
Create "My RAG"
      ↓
My RAG v1
```

That same artifact can then be used in:

```text
                 My RAG v1
                     │
          ┌──────────┼──────────┐
          ↓          ↓          ↓
      Evaluation  Inference   LLMOps
          │          │          │
          ↓          ↓          ↓
       Quality    Performance Deployment
                                │
                                ↓
                            Monitoring
                                │
                                ↓
                              Problem
                                │
                                ↓
                           My RAG v2
                                │
                                ↓
                           Evaluation
```

This is **mandatory**, not an optional UX enhancement.

The user should feel that they are operating on the same AI system throughout its lifecycle.

# 35. Phase 1 — Local Implementation

**Phase 1 must not depend on GCP.**

Implement and validate locally first.

Use:

```text
Frontend
   ↓
Local Backend
   ↓
Local/mock persistence
   ↓
Mock/real AI providers
```

Where practical, provide:

* mock LLM provider
* deterministic datasets
* simulation mode
* local evaluation
* simulated GPU/inference behavior

The learning experience must remain usable without cloud infrastructure.

Use environment variables for API keys.

Never commit secrets.

# 41. User Testing Strategy

The user will manually test **each module immediately after completion**.

Therefore, implementation must be strictly incremental.

```text
MODULE 1
    ↓
Local verification
    ↓
User test
    ↓
Feedback
    ↓
Fix / improve
    ↓
MODULE 2
    ↓
Local verification
    ↓
User test
    ↓
...
```

Do not implement all five modules before user testing.

After every module, provide:

```text
- What was implemented
- How to run locally
- What the user should test
- Learning objectives covered
- Known limitations
- Expected behavior
```

Wait for user feedback before proceeding.

# 44. What Should NOT Be Overbuilt

The purpose is to demonstrate strong AI engineering, not to build a miniature hyperscaler.

Avoid spending excessive time on:

* frontier model training
* advanced ML research
* implementing every classical ML algorithm
* building an LLM framework
* Kubernetes
* distributed infrastructure
* complicated multi-agent systems
* permanent GPU infrastructure
* enterprise IAM complexity

Prioritize:

```text
AI understanding
+
AI application engineering
+
Evaluation
+
Inference
+
LLMOps
```
